# 옆자리 (YEOPJARI) — 기획서 원고 v2

> 공식 접수양식 「02 앱 프로젝트 소개 / 심사 자료」 1~7번 항목에 옮겨 쓸 수 있도록 작성했습니다.
> 개인정보·소속·실명은 기재하지 않습니다. 등장 인물·장소 기록은 가상의 페르소나와 합성 데이터입니다.

**앱명 / 프로젝트명:** 옆자리 (YEOPJARI) — 나를 아는 AI 동승자

---

## 1. 앱 한 줄 소개

**차량 음성인식이 장소 이름을 잘못 알아들어도 이 운전자의 방문 기록으로 바로잡고, 헷갈릴 때만 앞유리 HUD에 선택지 3개를 띄워 묻고, 고른 답으로 차 안에서 바로 배우는 온디바이스 개인화 AI입니다. 개인 데이터는 차 밖으로 나가지 않습니다.**

---

## 2. 기획 배경

### 2-1. 주목한 순간: "서심다응으로 안내합니다"
- 운전 중 "성심당 가자"라고 말하면 음성인식은 "서심다응"처럼 **비슷한 소리로** 틀립니다. 그러면 엉뚱한 곳을 검색하거나, 이름이 비슷한 다른 지점으로 안내하거나, 같은 말을 몇 번이나 다시 하게 됩니다. 결국 운전자는 휴대폰이나 터치스크린을 집어 듭니다. 가장 위험한 순간입니다.
- 차량 음성비서는 10년 넘게 J.D. Power 품질조사의 상위 불만 항목입니다. 2026 IQS에서 인포테인먼트는 품질이 유일하게 악화된 분야였고, 주의분산 불만의 46%가 터치스크린이었습니다. 2026년 출시된 Gleo AI 시승기에서도 구어를 잘 이해하지 못한다는 지적이 나왔습니다. 최신 차량에서도 "자꾸 다른 곳을 찾는다"는 경험은 흔합니다.

### 2-2. 왜 범용 모델만으로는 안 되는가
- **고유명사는 '모르는 단어' 문제입니다.** 단골 가게, 지점 이름, "엄마 집" 같은 개인 별칭은 모든 운전자에게 같은 범용 모델이 알 수 없습니다. 모델을 아무리 키워도 한계가 있습니다.
- **같은 말도 사람과 상황에 따라 다른 곳입니다.** 서준 씨의 "스타벅스"는 평일 아침이면 판교테크노밸리점, 주말 오전이면 잠실새내역점입니다. 정답은 이 사람의 생활 패턴 안에만 있습니다.
- **정확도를 끝까지 올려도 0%는 안 됩니다.** 그래서 '틀릴 수 있다'를 전제로, 틀렸을 때 운전자가 손을 쓰지 않고 바로잡을 수 있는 UX가 필요합니다.

### 2-3. 개인화의 딜레마: 맞춤형이 되려면 개인 데이터가 필요하다
- 어디를 언제 가는지는 가장 민감한 개인정보입니다. 이를 서버로 모아 학습하는 순간 유출·오용 위험과 사용자 불신이 생깁니다.
- 그래서 옆자리는 **개인 데이터를 차 밖으로 보내지 않고도 개인화가 되는 구조**를 목표로 설계했습니다(3·5번 항목).

## 3. 앱 주요 기능 및 차량 특화 요소

### ① 개인화 보정 엔진 — "들린 말"을 "이 사람이 지금 말했을 장소"로
- Pleos STT SDK가 준 텍스트("서심다응 가자")에서 명령 해석 모델이 장소 부분과 목적지/경유지를 뽑습니다.
- **발음 비교:** 글자가 아니라 '소리'로 비교합니다. 음절을 초성·중성·종성으로 풀고 받침은 실제 발음으로 바꾼 뒤, 비슷한 소리(ㅐ/ㅔ, ㅓ/ㅗ, 받침 ㅇ 탈락, ㅡ 삽입 등)는 작은 비용으로 계산합니다. 그래서 "서심다응"과 "성심당"은 가깝고 "성당"은 멉니다.
- **개인 기록 점수:** 차 안에만 저장된 방문 기록으로 후보마다 다섯 가지를 계산합니다. 얼마나 자주 갔는지, 지금 요일·시간대에 가던 곳인지, 현재 위치나 경로에서 가까운지, 최근에 갔는지, 전에 이 말로 고른 적이 있는지입니다.
- **확률:** 점수 = 가중치 × [발음, 자주, 시간대, 거리, 최근, 선호]로 계산하고 확률로 바꿉니다(조건부 로짓). 발음 항이 있어서 무슨 말을 해도 자주 가는 곳으로 끌려가지 않습니다.

### ② 확신도에 따른 3단계 행동 — 묻는 건 헷갈릴 때만
| 확신도 | 행동 | 예 |
|---|---|---|
| 85% 이상이고 2위와 차이가 큼 | **바로 실행**, 10초 안에 "아니야"로 되돌릴 수 있음 | "늘 가시던 스타벅스 판교테크노밸리점으로 안내할게요." |
| 50% 이상 | **한 번 확인** | "성심당 대전역점으로 갈까요?" → "응" / "아니야" |
| 그 밖 | **HUD 선택지 3개** | "어디로 갈까요? 1 성심당 본점 · 2 성심당 DCC점 · 3 대흥동 성당" → "1번" |

- 대답은 말로 합니다. "응", "아니야", "2번", "두 번째", "본점", "역에 있는 거"처럼 말해도 알아듣습니다. 주행 중에는 화면 터치 없이 끝납니다.
- 질문을 마치면 마이크가 자동으로 열립니다. "어", "잠깐만" 같은 군말에는 질문을 지우지 않고, "다시 말해줘"에는 다시 묻습니다.
- 경유지는 자동으로 추가하지 않고 항상 한 번 확인합니다. 바로 실행한 안내를 "아니야"로 취소하면 원래 경로로 되돌립니다.

### ③ 차 안 즉시 학습 — 고를수록, 틀릴수록 똑똑해진다
- 사용자가 고른 답이 곧 학습 데이터입니다. 고르는 순간 차 안에서 가중치 6개를 갱신합니다(경사 상승 1스텝, 수 밀리초).
- 들린 말이 이름과 달랐다면 **"서심다응 = 성심당"을 기억**합니다. 그 말로 고른 장소도 기억합니다. 그래서 같은 말을 두 번째로 하면 묻지 않고 바로 안내합니다.
- 명령 해석 모델(LoRA)은 주차·충전 중에 쌓인 정정 기록으로 갱신하도록 설계했습니다. 실시간 학습은 가벼운 순위 모델이 맡고, 무거운 학습은 차가 쉬는 시간에 합니다.

### ④ 앞유리 HUD 시뮬레이터 — 눈은 도로에, 선택은 말로
- 되묻기는 중앙 화면이 아니라 운전자 시선 앞 HUD에 띄웁니다. 질문 한 줄, 또는 번호가 붙은 후보 최대 3개(이름·근거·거리)만 보여 줍니다.
- 현재 Pleos 공개 SDK에는 HUD에 그리는 API가 없습니다. 그래서 **앱 안에 앞유리 시점의 HUD 시뮬레이터**를 만들어 같은 정보 구조를 에뮬레이터에서 실제로 동작시킵니다. HUD가 열리면 같은 화면을 그대로 투사할 수 있고, HUD가 없는 차량을 위해 중앙 화면 큰 버튼 3개와 음성으로도 똑같이 제공합니다.
- 주행 중(CarUxRestrictions)에는 분석 화면을 숨기고 HUD와 큰 버튼만 남깁니다.

### ⑤ 개인정보는 차 안에 — 보내는 것은 '숫자 6개'뿐
- 방문 기록·기억한 표현·가중치는 **AES-256-GCM으로 암호화**해 차 안에 저장합니다. 키는 Android Keystore의 하드웨어 보안 영역에 있어 꺼낼 수 없습니다.
- 학습 이력은 **해시 체인**으로 남깁니다. 블록체인의 '이전 기록 해시를 품는' 개념만 빌렸습니다. 중간 기록을 몰래 고치면 검증이 깨집니다.
- 공용 모델을 개선할 때는 **연합학습** 방식을 씁니다. 원본 기록은 보내지 않고 '가중치 변화량 6개'만 보냅니다. 이때 크기를 제한하고(클리핑), 잡음을 섞고(차등 프라이버시 방식), 차량 개인키로 서명합니다(ECDSA P-256). 앱 화면에서 실제로 보낼 내용을 그대로 미리 보여 줍니다.
- "내 기록 지우기" 한 번이면 그 자리에서 사라집니다. 기록을 모델 가중치에 외우게 하지 않고 수첩(DB)으로 두기 때문에 가능합니다.

### ⑥ Gleo와 함께 — 차량 AI가 놓친 것을 옆자리가 받친다
- "글레오야, 옆자리로 서심다응 가자"라고 하면 Gleo가 App Schema `GO_TO_MY_PLACE(place="서심다응")`로 옆자리를 호출합니다. 옆자리는 개인 기록으로 보정한 뒤 확신이 낮을 때만 HUD로 묻습니다.
- Gleo를 대체하지 않고, Gleo의 음성인식 결과 위에 **개인화 보정 계층**을 얹는 구조입니다.

### ⑦ 같은 엔진 위의 생활 기능
- 충전 코파일럿(도착 배터리 예측·충전소 신뢰도), 단계별 졸음 케어, 펫 케어, 아이 동승, 주차 위치 음성 메모, 경고등 해설은 같은 대화·안전 정책·차량 SDK 계층 위에서 동작합니다.

## 4. 주요 사용 시나리오 — 운전자 1명(가상 페르소나 '서준')이 개인화되는 과정

**서준(38)**: 잠실 거주, 판교 출근, 아이 둘. 격주 토요일마다 대전 본가에 가는 길에 성심당 대전역점에 들러 빵을 삽니다.

### 4-1. 개인화가 만들어지는 과정
| 시점 | 차 안에 쌓인 것 | 옆자리의 행동 |
|---|---|---|
| 첫날 | 기록 없음 | 발음 보정만 가능. "서심다응" → 성심당 지점 3곳과 성당을 후보로 HUD 선택지 제시 |
| 2주 | 주차(P) 위치·목적지 이력이 방문 기록으로 쌓임 | 자주·시간대·경로 점수가 생겨 '평일 아침 스타벅스 = 판교점'을 바로 안내 |
| 첫 정정 | "아니야 → 1번" 같은 선택 | 가중치 갱신, "서심다응 = 성심당" 표현 기억 |
| 1개월 | 방문 90일 창, 선택 기억 | 되묻기는 애매한 순간에만. 같은 말은 바로 실행 |

### 4-2. 토요일 오전, 대전 본가 가는 경부고속도로 (시연 시나리오)
1. "서심다응 가자" → STT 텍스트 → 명령 해석: {길안내, 장소 "서심다응"}
2. 보정 엔진: 성심당 대전역점이 1위(발음 0.89 · 주로 토요일 오전 · 5회 방문 · 가는 길), 그다음 본점 · DCC점 · 대흥동 성당
3. HUD: "성심당 대전역점으로 갈까요?" → "응" → NaviHelper로 안내 시작, HUD에 "기억했어요 · ‘서심다응’ = 성심당"
4. 다음에 같은 말을 하면 바로 실행: "늘 가시던 성심당 대전역점으로 안내할게요." 10초 안에 "아니야"로 취소할 수 있습니다.
5. 다른 경우: 2단계에서 "아니야" → HUD에 본점·DCC점·대흥동 성당 → "1번" → 본점으로 안내하고 그 선택을 학습합니다.

### 4-3. 같은 말, 다른 정답
- **평일 08:31 판교 출근길:** "스타벅스 가자" → 판교테크노밸리점으로 바로 안내
- **토요일 10:50 잠실 집 앞:** 같은 말 → "스타벅스 잠실새내역점으로 갈까요?"
- **"빵집 들렀다 가자":** 종류로 말해도 대전 가는 길이면 성심당, 평일 저녁 집 근처면 파리바게뜨를 경유지로 제안합니다.
- **"엄마 집 가자":** 개인 별칭 → 대전 본가

### 4-4. 내 기록 관리
- '맞춤 AI' 화면에서 AI가 고른 이유(특징별 점수), 차 안에서 배운 것(가중치·기억한 표현), 서버로 보낼 내용 미리보기, 학습 기록 사슬을 봅니다. "내 기록 지우기"를 누르면 즉시 처음 상태로 돌아갑니다.

## 5. 개발 계획

### 5-1. 현재 구현 (Pleos Connect 에뮬레이터 v2.1.0에서 구동)
- 개인화 보정 엔진(발음 비교·순위 모델·차 안 학습), 되묻기 대화(확인·선택지·되돌리기), 앞유리 HUD 시뮬레이터, 암호화 저장소·해시 체인·서명된 업데이트 미리보기, Gleo `GO_TO_MY_PLACE`
- 실차 SDK 연동 검증: CarUxRestrictions 주행 모드 전환, NaviHelper 경유지 요청 수신, 온디바이스 TTS 출력, HVAC 제어 반영, Gleo 콜백 수신
- 정확도 평가 코드: 실제 앱 엔진 코드를 그대로 JVM 테스트로 돌립니다(docs/eval/personal_eval.md).

### 5-2. SDK / API 사용 계획
| SDK | 쓰는 곳 |
|---|---|
| SpeechToText 3.3.1 (온디바이스) | 음성 → 텍스트. 차량 마이크 음성은 STT SDK로만 처리하고 외부 전송 없음 |
| NaviHelper 3.0.5 | 보정된 장소로 requestRoute / addWaypoint, 현재 경로(목적지)로 '가는 길' 점수, 최근 목적지·즐겨찾기·도착 이벤트로 개인 장소 사전, 제한속도는 HUD |
| FusedLocation 1.1.3 | 현재 위치 → 거리 점수, 주차 위치 → 방문 기록 |
| Vehicle 2.3.2 · AAOS Car API | 기어 P 진입 시 방문 기록, 차속·UX 제한으로 주행 중 화면 전환 |
| TextToSpeech 3.3.1 | 확인 질문·안내 음성 |
| Gleo App Schema | `GO_TO_MY_PLACE(place, stop_type)` · `PLAN_EV_TRIP` · `START_CARE_MODE` |

### 5-3. AI 구성과 학습 계획
- **명령 해석(온디바이스):** Qwen3-0.6B(Apache-2.0)에 차량 명령 LoRA를 붙입니다. 문장을 JSON 한 줄(의도·장소·목적지/경유지·종류)로 바꾸고, 음성인식 오타를 섞은 합성 데이터로 학습해 오타에 강하게 만듭니다. 4비트 양자화(GGUF, 약 0.4GB)로 차 안에서 300ms 안에 처리하는 것이 목표입니다. 학습·평가 파이프라인은 저장소 `ml/`에 있고 B200 1/7 GPU에서 돌아가도록 구성했습니다.
- **개인화(온디바이스):** 순위 모델 가중치 6개 + 표현·선택 기억. 학습은 차 안에서 즉시 합니다.
- **공용 모델 개선(선택 동의):** 연합학습. 서명된 가중치 변화량만 모으고 원본 기록은 모으지 않습니다.
- **향후 확장:** 현대가 STT의 단어 부스트·후보 문장·화자 등록 기능(SDK 안에 시스템 앱 전용으로 존재)을 열면, 옆자리가 사용자별 부스트 목록을 매일 만들어 넣어 인식 단계부터 정확도를 높일 수 있습니다.

### 5-4. 정확도 평가 (가상 운전자 1명, 처음 보는 미래 4주 · 합성 음성인식 오류)
- 방법: 엔진이 본 적 없는 미래 4주 동안 간 곳 41건 × 세 가지 말투(이름 그대로 / 음성인식 오류가 섞인 이름 / '빵집' 같은 종류어) = 질의 121개. 앱의 엔진 코드를 그대로 JVM 테스트로 돌렸습니다(seed 고정, 손으로 고친 숫자 없음).

| 방법 | Top-1 | HUD 3개 안에 정답 | 확인 없이 엉뚱한 곳 출발 | 바로 맞게 출발 |
|---|---:|---:|---:|---:|
| 일반 검색(글자 일치 + 가까운 순) | 38.0% | 51.2% | 0.0% | 34.7% |
| 발음 보정만 | 62.0% | 100.0% | 0.0% | 53.7% |
| **발음 + 개인 기록 (옆자리)** | **95.0%** | **100.0%** | **0.0%** | 56.2% |
| **+ 차 안 학습** | **95.0%** | 100.0% | **0.0%** | **73.6%** |

- 음성인식 오류가 섞인 이름: 일반 검색 0% → 발음 보정만 63.4% → 옆자리 95.1%
- 평가 데이터를 5번 새로 뽑아 반복한 평균 Top-1: 일반 검색 38.5% · 발음 보정만 66.1% · 옆자리 95.9%
- 장소 사전에 없는 곳을 말했을 때 엉뚱한 곳으로 바로 출발: 발음 보정만 52% → 옆자리 0%
- 한계: 합성 페르소나와 흉내 낸 음성인식 오류로 잰 값입니다. 2차 PT까지 실제 주행 기록과 실제 STT 결과로 다시 측정합니다. (상세: `docs/eval/personal_eval.md`)

## 6. 기대효과 및 발전 가능성

### 6-1. 사용자 가치
- **안전:** 잘못 알아들었을 때 화면을 만지거나 휴대폰을 드는 일이 줄어듭니다. 되묻기는 시선 앞 HUD와 음성 번호로 끝납니다.
- **시간:** "다시 말하기"를 반복하지 않습니다. 같은 말은 두 번째부터 바로 실행합니다.
- **신뢰:** 내 기록은 차 안에만 있고, 무엇을 배웠는지와 무엇을 보내는지 화면에서 확인하고 지울 수 있습니다.

### 6-2. 타깃 고객
- 매일 운전하는 출퇴근자(수도권 왕복 83.2분): 같은 장소를 반복 방문해서 개인화 효과가 가장 빨리 쌓입니다.
- 가족 운전자: 가족마다 부르는 이름이 다른 장소("엄마 집", "도윤이 유치원")
- 음성인식 불만 사용자: 사투리, 빠른 말, 외래어 상호를 자주 쓰는 운전자
- 진입 시장: 국내 Pleos Connect 탑재 현대·기아·제네시스(2030년 2,000만 대 탑재 목표)

### 6-3. 예상 MAU · Retention
- 가정: Pleos 탑재 국내 누적 대수 × 설치율 × 설치 대비 MAU 65%
  - 2027: 80만 대 × 15% × 65% ≈ 7.8만
  - 2028: 180만 대 × 22% × 65% ≈ 25.7만
  - 2029: 300만 대 × 30% × 65% ≈ 58만 + 해외
- Retention 목표: D30 45%, M6 35%. 목적지 음성 명령은 매일 생기고, 쓸수록 정확해지는 구조라 이탈 동기가 줄어듭니다.

### 6-4. 수익·사업화
- **OEM 라이선스:** 개인화 보정 계층을 Gleo·STT의 기능 모듈로 공급합니다(온디바이스, 개인정보 서버 수집 없음).
- **장소 제휴:** 단골 매장 혜택, 주차·충전 연계(동의 기반, 개인 기록은 차 안에서만 매칭)
- **선택형 구독:** 가족 프로필, 개인 별칭 동기화(종단 간 암호화)

### 6-5. 확대 계획
- 장소 다음으로 **사람·음악·기능 이름**으로 확장합니다. 예: "엄마한테 전화해", "그 노래 틀어", "엉뜨 켜줘".
- 가족 공유 차량은 화자별 개인화를 적용합니다(STT 화자 정보 연계).
- 연합학습으로 지역 상호·별칭 사전과 공용 명령 해석 모델을 함께 개선합니다.
- 해외: 언어별 발음 규칙만 바꾸면 같은 구조를 쓸 수 있습니다(한국어 자모 비교 → 언어별 음소 비교).
