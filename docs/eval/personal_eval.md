### 비교한 방법

| 방법 | 설명 | ‘바로 실행’ 기준 |
|---|---|---|
| A 일반 검색 | 장소 이름·별칭·브랜드에 들린 말이 글자 그대로(띄어쓰기 무시) 들어 있는 곳, 가까운 순. 글자가 안 맞으면 못 찾음 | 결과가 1곳뿐일 때 |
| B 발음 보정만 | 엔진의 발음 유사도(`Hangul.similarity`, 이름 중 최댓값 · 범주어면 범주 일치)만, 같으면 가까운 순. 개인 기록 없음 | 1위 점수가 혼자일 때 |
| C 발음+개인 기록 (옆자리) | `PersonalBrain.resolve` 기본 가중치 [6.0, 1.6, 1.4, 1.0, 1.0, 2.0], 학습 없음 | 엔진 등급 (p1 ≥ 0.85, p1−p2 ≥ 0.5, 1위 발음 ≥ 0.8) |
| D C + 차 안 학습 | C와 같되 질의마다 앱의 대화 흐름대로 `learn` 호출: 바로 실행이 맞으면 lr 0.3(10초 무응답), “응”·“n번”·“아니야→n번”이면 lr 0.6, 정답이 화면 후보에 없으면 학습 없음. “아니야”로 거절한 1위는 그 말의 선택 기억에서 한 번 덜어 냄(`forgetChoice`) | 엔진 등급 |

- 거리는 엔진과 같은 정의(안내 중이면 경로까지의 거리, 아니면 직선거리)를 A·B의 동점 처리에도 쓴다. 후보 기준(발음 ≥ 0.55)도 B·C·D가 같다.
- C·D는 질의 뒤 그날 실제 방문을 기록에 더한다(`replaceVisits(visits + v)`). 방법마다, 말투마다 새 엔진으로 28일을 따로 다시 달린다 — 여정 하나에 질의 하나·학습 하나.
- 지표: **Top-1** 첫 후보가 정답 · **Top-3** HUD 선택지(최대 3개) 안에 정답 · **자동 실행** 확인 없이 바로 안내 · **잘못된 자동 실행** 바로 안내했는데 틀림(전체 질의 대비) · **되묻기** 한 번 확인 또는 선택지 · **못 찾음** 후보 없음.

## 4. 발견한 점

- **발음 보정과 오류 섞인 이름**: B의 Top-3가 (a) 100.0% → (b) 100.0%로 거의 그대로다 (글자 일치 A는 (b)에서 Top-1 0.0%). 발음만으로는 지점이 여럿인 브랜드(스타벅스·성심당·현대백화점)와 범주어에서 어느 곳인지 가리지 못해, 동점이면 가까운 곳을 고른다.
- **개인 기록과 ‘어느 지점’**: 같은 질의에서 C만 맞힌 것 40건, B만 맞힌 것 0건 — 시간대·경로·최근 방문이 같은 브랜드의 지점과 범주어의 대상을 가른다.
- **차 안 학습(C → D)**: 바로 실행 +21건, Top-1 +0건, 잘못된 자동 실행 0건 → 0건 — 학습은 정확도보다 확신(확인 질문을 건너뛰는 비율)을 바꿨다.
- **무엇을 기억했나** (28일 뒤 D): 이름을 그대로 말한 (a)에서 남은 선택 기억 0개·표현 0개 — 정확한 이름(스타벅스·성심당…)은 이미 알아들으므로 기억하지 않는다. 같은 오인식이 반복되는 (b′)에서는 선택 기억 9개·표현 9개 (예: ‘해솔유칭원’ = 해솔유치원, ‘스타벅슨’ = 스타벅스, ‘횬대백화저음’ = 현대백화점).
- **아주 먼 곳도 크게 깎이지 않는다**: 거리 특징이 0~1 범위라 아무리 멀어도 점수가 최대 1.00점(거리 가중치)만 줄어든다. 시연 P_DAEJEON의 고속도로 위 “빵집 들렀다 가자”에서 116km 떨어진 파리바게뜨 잠실레이크점이 23% (평일 저녁 단골이라 ‘자주·최근’ 점수가 높다). 1위는 맞고 행동이 ‘한 번 확인’이라 틀린 답은 아니지만, 경유지 질의에서 경로와 먼 곳을 거르면 확신이 오를 여지가 있다.
- **지금 목적지가 경유지 후보로 나온다**: 대전 본가로 안내 중에 “송심당 들렀다 가자”라고 했는데 대전 본가가 9%로 3위 안에 든다. 경유지(‘들렀다 가자’) 질의에서는 현재 목적지를 후보에서 빼는 규칙을 넣을 수 있다 — 이번 평가에서는 엔진을 바꾸지 않았다.

## 5. 이번 평가에서 찾아 고친 엔진 버그

1. **`QueryParser` 말머리 군말 제거**: ‘음·어·그’ 같은 군말을 단어 경계 없이 떼어 ‘어린이집 들렀다 가자’ → ‘린이집’, ‘그랜드 하얏트’ → ‘랜드 하얏트’, ‘어마 집’(엄마 집의 오인식) → ‘마 집’으로 잘렸다. 군말 뒤에 띄어쓰기·쉼표가 있을 때만 떼도록 정규식 한 줄을 고쳤다 (회귀 테스트 `parse_fillerIsStrippedOnlyAsSeparateWord`).
2. **`PersonalBrain` 바로 실행 판단**: 확률은 후보끼리의 상대값이라, 사전에 없는 곳을 말해 소리가 약하게만 비슷한 후보 하나가 남으면 확률이 1.0이 되어 확인 없이 출발했다 (‘다이소’ → 성심당 본점, ‘한강공원’ → 올림픽공원). 바로 실행에 ‘1위 발음 유사도 ≥ 0.8’ 조건을 더했다 (`AUTO_MIN_PHON`, 회귀 테스트 `weakSoundAlike_neverStartsWithoutAsking`). 순위·확률은 그대로이고, 조건에 못 미치면 ‘한 번 확인’이 된다.
   - 영향 (C, 같은 질의의 반사실 비교): 사전에 없는 곳 100개 중 바로 실행 29건 → 0건 · 사전에 있는 곳 121개 중 바로 실행 68건 → 68건.
   - 기준값 0.8은 seed 99~103의 분포를 보고 정했고, 겹치지 않는 seed 200~209와 다른 사전 밖 장소 30곳으로 확인했다: 사전에 있는 곳(C)에서 옛 규칙의 바로 실행 824건 중 기준 미달로 ‘한 번 확인’이 된 것 3건(모두 정답 — 운전자가 “응” 한 번 더 말하는 비용), 옛 규칙에서도 잘못된 바로 실행은 0건. 사전에 없는 곳 240개(C·D, seed 200의 28일 뒤 엔진)에서 옛 규칙의 바로 실행 66건 중 66건이 막혔다.

### 코드 리뷰에서 고친 학습·대화 규칙 (위 숫자는 모두 고친 뒤)

3. **선택 기억 = 평일·주말로 나눈 ‘고른 몫’** (`PersonalBrain.choiceShare`): 전에는 같은 말로 한 번이라도 고른 곳의 ‘선호’가 1.0이라, 평일에 고른 곳이 주말의 같은 말까지 끌고 갔다(지난 평가의 D만 틀린 질의). 이제 선호 = 같은 요일 종류(평일·주말)에 그 말로 고른 기록 중 이 곳의 몫, 그 요일 종류의 기록이 없으면 전체 몫의 절반이다. 시연 좌표로 계산: 평일 출근길에 ‘스타버스’로 판교점을 3번 고른 뒤 토요일 10:50 집 앞에서 같은 말 → 판교점 선호 0.50, 1위 스타벅스 잠실새내역점 49.3% · 토요일에 잠실새내역점을 한 번 고른 뒤 → 토요일 1위 스타벅스 잠실새내역점, 평일 출근길 1위 스타벅스 판교테크노밸리점 · 평일에 판교 2번·강남 1번이면 선호 0.67 / 0.33. 거절(“아니야”)하면 그 곳의 횟수를 한 번 덜어 낸다 (회귀 테스트 `choiceMemory_isShareSplitByWeekdayWeekend`).
4. **오인식을 바로잡은 선택만 기억** (`PersonalBrain.learn`): 전에는 고른 곳이 무엇이든 ‘들린 말 → 장소’ 표현과 선택 기억을 남겨, 확인 단계의 “아니, 병원”이 ‘스타벅스 = 소아과’로 기억됐다. 이제 고른 곳의 발음 유사도가 0.8 이상이고 들린 말이 어떤 장소의 정확한 이름도 아닐 때만 남기며, 이미 기억한 표현은 그 말로 새 곳을 고른 횟수가 옛 곳보다 많아져야 바뀐다. 가중치 학습은 그대로 한다 (회귀 테스트 `learn_onlyMemorizesCorrectedMishearings`, `learn_aliasNeedsMoreVotesToChange`).
5. **대답 해석** (`QueryParser.reply`·`matchOption`): “네 가 주세요”·“그렇게 해 줘”·“거기로 가자”·“1번 안내해 줘”·“네 번째”가 대답으로 읽히고(4번 이상은 번호 그대로 넘겨 범위 안내), 혼자 말한 “어”는 ‘네’가 아니다. 이름 일부로 고를 때는 긴 이름 안의 아무 부분이 아니라 지점 이름 단어·별칭과 비교해 ‘그거요’·‘빨리’·‘노래’가 엉뚱한 지점에 붙지 않는다 (회귀 테스트 `reply_*`, `matchOption_*`). 재검토에서 “아냐”·“그거 아니야”·“잘못 들었어”·“노노”(부정), “좋지”·“그러자”·“가 보자”·“응 고마워”(긍정), 제안한 곳의 이름(“성심당 맞아”)도 대답으로 읽고, “뭐라고?”·“잠깐만”·“어…”(다시 묻기·기다리기·머뭇거림)는 질문을 지운 채 새 명령으로 넘기지 않는다 — 질문을 내리는 것은 진짜 새 명령뿐이다 (회귀 테스트 `DialogueParsingTest`, `DialogueStoreTest`).
6. **섞인 명령 거르기** (`QueryParser.parse`, 의도 엔진): “졸려서 휴게소 들렀다 가자”, “에어컨 켜고 집으로 가자”, “스타벅스 말고 회사로 가자”처럼 다른 의도의 말·부정·앞 절(…고/…서/…는데)이 섞이면 장소 명령으로 보지 않는다. 재검토에서 ‘…고’는 동사 줄기 뒤(먹고·켜고·데리고)에서만 앞 절로 보고(‘잠실고 정문’·‘망고 식스’·‘중고 서점’은 장소), “빨리 가자”·“그냥 가자”처럼 부사뿐인 말은 장소 명령이 아니며(앞에 붙은 부사는 뗀다), “성심당 들렀다 가 줘”·“들러 주세요” 같은 부탁 꼴은 경유지로 읽는다. 두 음절 이하의 짧은 말은 이름 안의 일부가 아니라 이름의 단어 전체와 소리를 비교한다(‘빨리’ ↔ ‘…밸리점’ 방지). 평가 문장(121개)의 해석 결과는 위 ‘문장 해석’ 그대로다 (회귀 테스트 `parse_rejectsMixedCommands`, `appIntentEngine_mixedCommandsGoToTheirOwnIntent`, `parse_d6_*`, `parse_d7_*`, `parse_d10_*`).

## 6. 한계 — 이 숫자가 말하지 않는 것

- **합성 페르소나**: 평가 여정은 학습 기록과 같은 생성기(같은 생활 패턴)에서 나왔다. 실제 사람은 덜 규칙적이고 새 장소에도 가므로, 개인 기록을 쓰는 C·D에 유리한 조건이다. 실제 주행 로그(NaviHelper 목적지 이력·주차 위치)로 다시 재야 한다.
- **흉내 낸 음성인식 오류**: 자모 규칙으로 ‘비슷한 소리로 틀리기’만 흉내 냈다. Pleos STT의 실제 오류 분포(단어 통째 바뀜, 영어 브랜드 표기, 소음 속 음절 누락 등)와 다르며, 실제 녹음으로는 재지 않았다.
- **한 사람, 장소 사전 21곳**: 이미 아는 장소를 다시 찾아가는 경우만 정확도를 쟀다. 처음 가는 곳은 위 ‘처음 가는 곳’ 표처럼 거절·되묻기 비율만 봤고, 그 뒤 내비 검색으로 넘기는 연결은 앱에 아직 없다. 사전이 작아서 소리 오류에 강하게 나온 면도 있다 — 실제 POI DB를 뒤지면 비슷한 소리의 후보가 훨씬 많아 A·B는 더 헷갈린다.
- **학습 신호는 이상적**: D는 운전자가 늘 맞는 곳을 확인·선택한다고 가정했다(앱 대화 흐름 그대로, 화면에 없는 후보는 학습하지 않음). 잘못 누른 선택이 섞이면 학습이 흔들릴 수 있다.
- **작은 표본**: 질의 121개라 신뢰구간이 넓다(위 표). 문장은 “<장소> 가자” 틀만 썼고, 차 위치는 직전 방문지로 단순화했다. A·B의 ‘바로 실행’은 결과가 하나뿐일 때로 정의했다(실제 내비 검색은 보통 목록을 보여 준다).
- **A는 엄격한 기준선**: 오타 허용 없는 글자 일치로 정의했으므로 (b)에서 0%가 나오는 것은 정의상 당연하다. 상용 검색의 오타 보정·초성 검색은 이보다 낫다. 또 A는 이름 글자만 보므로 ‘빵집’·‘카페’처럼 이름에 없는 범주어는 못 찾는다 — 실제 내비의 ‘주변 빵집’ 검색은 B의 (c) 결과(범주 일치 + 가까운 순)에 가깝다.
- **쉬운 질의가 많다**: 유치원처럼 이름이 하나뿐인 곳의 반복 방문이 질의의 큰 몫이라 모든 방법의 숫자를 함께 끌어올린다. 방법 사이의 차이는 장소별 표에서 보는 것이 정확하다.
